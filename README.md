## Описание

Проект посвящён исследовательскому анализу данных агентства недвижимости.
База данных состоит из шести таблиц: `agents`, `clients`, `properties`,
`listings`, `viewings`, `deals`. С помощью SQL-запросов исследуется
эффективность работы агентов, поведение клиентов, успешность объявлений
и этапы воронки продаж.

Логическая цепочка данных: **объект → объявление → просмотр → сделка**

## Структура репозитория

```
sql_project/
├── README.md
├── 00_data_understanding/       # первичный анализ и проверка данных
│   ├── 01_table_preview.sql     # обзор структуры таблиц (SELECT * LIMIT 5)
│   ├── 02_row_counts.sql        # количество строк в каждой таблице
│   ├── 03_null_checks.sql       # проверка на NULL-значения
│   └── 04_relationship_checks.sql # проверка целостности связей (LEFT JOIN)
└── hypotheses/                  # 15 гипотез, каждая — отдельный файл
    ├── hypothesis_01.sql
    ├── hypothesis_02.sql
    ├── ...
    └── hypothesis_15.sql
```

Каждый файл в `hypotheses/` содержит:
- формулировку гипотезы,
- SQL-запрос,
- вывод по результатам.

## Ключевые сущности

| Таблица | Первичный ключ | Описание |
|---|---|---|
| `agents` | `agent_id` | агенты агентства недвижимости |
| `clients` | `client_id` | клиенты |
| `properties` | `property_id` | объекты недвижимости |
| `listings` | `listing_id` | объявления (связывают объект, агента и продавца) |
| `viewings` | `viewing_id` | просмотры объектов клиентами |
| `deals` | `deal_id` | завершённые сделки (связывают объявление и покупателя) |

## Проверка данных

Во всех таблицах пропущенные значения (NULL) отсутствуют. Проверка связей
между таблицами (через `LEFT JOIN`) не выявила записей-сирот — база данных
целостна и пригодна для анализа.

## Общие паттерны

**Что работает хорошо:**
- Часть агентов стабильно показывает высокие результаты по количеству сделок.
- Квартиры вызывают наибольший интерес у клиентов среди всех типов недвижимости.
- Данные целостны: нет пропусков и нарушенных связей между таблицами.
- Между офисами нет сильной разницы в конверсии объявлений в сделки, несмотря на разный объём работы.

**Где потери:**
- Не все объявления получают просмотры, а часть просмотров не переходит в сделку.
- Есть клиенты с высокой активностью просмотров, но без покупок.
- Большое количество объявлений не всегда приводит к большему числу сделок.

## Рекомендации бизнесу

- Проанализировать объявления, которые долго остаются без просмотров или сделок, и пересмотреть цену, описание или фотографии.
- Регулярно анализировать эффективность офисов и обмениваться успешными практиками между ними и сотрудниками.
- Изучить опыт наиболее успешных агентов и использовать их подходы при обучении остальных.
- Уделить больше внимания клиентам, которые часто просматривают объекты, но не покупают — выяснить причины.
- Продолжать регулярный контроль качества данных.
